# Product and rules, defined before implementation
Primary user: service-center clerk. Promise: explicit recipient confirmation and attributable custody from intake to pickup. Demo staff: Alex Rivera; organization maple-demo; timezone America/New_York. Local trusted workstation only.
P0: customer/mailbox/alias maintenance; image/manual/barcode intake; evidence-based suggestions and explicit confirmation; exception review; duplicate review; bilingual notification drafts and deterministic attempts; search, storage, pickup and separate authorization; immutable history, corrections and CSV.
Parking lot: billing, real OCR provider, live delivery, production authentication, identity services, certification.
Entities: Customer has Mailbox and CustomerAlias; MailItem references recipient, StorageLocation and LabelImage; OCRRun preserves source suggestions; MatchCandidate records evidence; IntakeConfirmation records clerk choice; PickupAuthorization independently records third party and staff check; CustodyEvent and AuditEvent append only; NotificationDraft has DeliveryAttempt with stable unique key.
State transitions: received → available/exception/returned; available → collected/returned/exception; exception → available/returned. Terminal collected and returned cannot transition. Corrections append history and regenerate unsent drafts. SQLite immediate transactions serialize collection. All queries use fixed demo organization; request IDs cannot select another business.
Acceptance scenarios: manual intake confirmed and persists after restart; Maria Garcia returns two candidates and requires evidence; inactive recipient rejected; duplicate available tracking requires reason; two concurrent pickups produce one event; correction retains history and changes unsent draft; Spanish messages expose only own item; failed and simulated attempts distinct from delivery; retry uses same key; expired labels deleted with audit.
